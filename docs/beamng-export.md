# BeamNG.drive export reference

[Documentation index](README.md) | [Project overview](../README.md)

See [Water in BeamNG exports](water-export.md) for automatic USGS/OSM lakes and river surfaces, caching and limitations.

This reference retains implementation notes in their original order. Later corrections supersede earlier behavior. BeamNG source downloads are now cached for seven days.

## BeamNG.drive v0.40 export

Select a discovered road (or open a Favorite), then choose **Generate BeamNG map**. Exports use 0.5 miles padding per side and 2048 terrain resolution. Generation runs in the existing server worker; progress and cancellation appear beside the road and on SuperAdmin Manage. Downloads are private to their owner. Ready ZIPs expire after 30 minutes; the application cleanup cron removes temporary files. Generate again after expiry.

Copy the downloaded ZIP into your BeamNG.drive user folder's `mods` directory without unpacking it. Open Free Roam and select the exported road. Start is the default spawn; End faces back toward Start for simulation, including roads mapped one-way. These are experimental generated levels targeting 0.40. The package format was checked against an installed 0.40.4 level; actual in-game loading and driving remain unverified.

The road fits inside a square geographic footprint with configurable padding (default 0.5 miles per side), projected into local UTM meters at real-world scale. Mapped lane counts, directional counts and widths are used where available; missing values use documented estimates in the included report. Lane-aware markings and building geometry are generated by SweepLine; stock vegetation, guardrails and asphalt detail are referenced from the game without redistributing its assets. Scenery placement uses aerial color heuristics, not authoritative object recognition.

Elevation comes from USGS 3DEP and aerial colors from USDA NAIP via USGS ImageServer HTTPS requests. Missing coverage, invalid elevation or failed downloads produce a visible failed job rather than fabricated terrain. The first version supports the continental US, a maximum square side of 32,768 meters, 20,000 road samples and 500 source pieces. Fixed beam/slab bridges and viaducts up to 2,000 metres can use approach-derived estimated decks; unsupported structural types remain refused. Ordinary fully contained single-bore tunnels can use estimated profiles and generated interiors; see the tunnel limits below. Untagged structures, coarse elevation, sharp interpolation, road banking and guessed scenery require review. A connected navigation graph represents the selected road for the minimap; traffic behavior still requires in-game validation. This is not a surveyed replica.

Upgrade with `sudo ./setup.sh`: migration `014_beamng_exports.sql` adds the private export queue, the installer adds missing `gdal-bin`, and the existing application worker processes jobs. No new persistent runtime or public service is introduced. PHP CLI requires GD, ZipArchive and zlib, and GDAL commands `gdalwarp`/`gdal_translate` must be executable by the application account. The installer configures minute-by-minute `bin/cleanup-beamng.php` cleanup. Workspaces are under private `var/beamng`, outside the document root. At least 512 MiB free disk is required before generation; queue limits are three active jobs per account and twenty globally. Source rasters are deleted when generation finishes; cancellation and failures also remove temporary files.

The authenticated API is `POST /api/beamng`, `GET /api/beamng/{id}`, `GET /api/beamng/{id}/download`, and `POST /api/beamng/{id}/cancel`. Creation accepts an owned `favorite_id` or a current `road_id`, profile and optional validated `member_ids`, plus `padding_miles` (0.1–5) and `resolution` (1024 or 2048). The server resolves geometry; clients cannot supply arbitrary remote URLs or map geometry. SuperAdmin cancellation uses `POST /api/admin/beamng/{id}/cancel`. State changes use existing CSRF protection.

Run `php tests/run.php` with the zip and gd extensions for offline binary/package, lane, terrain orientation and spawn checks. `--keep-beamng-fixture` additionally writes `var/beamng-validation.zip`, an explicitly synthetic verification level. These tests do not establish live provider/GDAL availability or in-game compatibility. Export packages include OSM/USGS/USDA attribution and an approximation report.

BeamNG provider timeouts and temporary HTTP errors are retried up to three attempts, waiting five then ten seconds. Manage and road export progress identify the elevation or imagery source and retry attempt. Cancellation remains active during downloads and retry waits. Exhausted retries fail the job; generate again later if the provider remains unavailable.

BeamNG map cards include the SweepLine label and road name. Start/End spawn cards have separate labeled aerial-map previews. Previews are map views, not in-game screenshots. Imagery explicitly uses the USGS NaturalColor rendering template; neutral daylight settings avoid relying on unspecified sky lighting. Spawn points move inward from road endpoints and use lane-centered right-hand placement with road-grade alignment. Regenerate old exports to obtain these updates.

BeamNG exports include generic START and FINISH arches centered across the road at the spawn locations. Supports stand two meters outside each road edge, the beam has six meters of clearance, and labels appear on both sides. Arches and lettering are generated assets; regenerate an export to include them.

Road surfaces now use 3 cm clearance above the shaped corridor to reduce terrain clipping. Spawn and arch transforms serialize contiguous basis-axis columns; arches remain upright across the road while spawn frames follow grade. Regenerate older maps to apply these changes.

The BeamNG action appears beside GPX/KMZ/PDF. Generate becomes an orange Download link when the private ZIP is ready; status and cancellation remain below the export row. Padding/resolution controls are removed from the UI; defaults are 0.5 miles and 2048. Road clearance is now 8 cm. Finish always faces Start for simulation; mapped one-way navigation data still describes the source road direction.

BeamNG source downloads are cached privately for seven days in `var/beam-resources/`. Validated DEM/NAIP TIFFs and OSM building, land-use and guardrail responses are reused only for an identical provider request (including bounds, projection, resolution and query). Cache hits retain their original acquisition date; reads do not extend the lifetime. Expired or corrupt inputs are downloaded again. The existing cleanup task prunes expired cache data automatically. Generated geometry and ZIPs are rebuilt; finished ZIP downloads still expire after 30 minutes. Per-job intermediate files are removed after completion, failure or cancellation, while validated shared source inputs remain until cache expiry.

BeamNG 0.40 samples terrain base textures in grid units. Export material BaseTexSize fields therefore use terrain resolution, while squareSize retains the real-world meter spacing. The aerial PNG remains north-up to match the shader''s Y flip. This avoids stretching a small portion of the imagery across a large map. Road clearance is 10 cm; regeneration is required for existing ZIPs.

BeamNG road clearance is now 25 cm. Vehicle spawn frames include a 180-degree facing correction at both endpoints, preserving their lane positions and leaving arch orientation unchanged. Generate a fresh ZIP after upgrading.

Road-height behavior has been restored to the initial BeamNG exporter: the MeshRoad surface is 0.25 m above smoothed sampled elevation, and corridor terrain is recessed 0.60 m below the road surface. This supersedes the later clearance adjustments. Texture alignment and spawn/arch orientation fixes remain in place. Regenerate exports to apply the restored offsets.

New BeamNG exports download elevation on the original 1024 grid, including the original half-cell alignment, while aerial imagery and exported terrain remain 2048 by default. Road heights are sampled directly from the original elevation grid before existing smoothing/offsets. Terrain is bilinearly upsampled from those samples; this adds grid vertices, not extra elevation detail. The report records elevation_sampling_resolution separately from terrain_resolution. Texture alignment, arches, spawn fixes and fresh-download behavior are retained. Previously generated ZIPs are never modified; regenerate to use this change. Fresh provider data may differ from historical downloads.

## Estimated bridges in BeamNG exports

Structure tags are checked against collinear overlap with the selected road (0.1 m geometric tolerance), rather than rejecting the full underlying OSM way. Crossings and nearby parallel structures do not count. Matching is bounded to two million segment comparisons and fails explicitly if too complex.

Fixed bridges tagged bridge=yes or bridge=viaduct, with missing/beam/slab bridge:structure and layer magnitude at most one, can be estimated. Spans must be 8–2,000 meters long and at most 20 meters wide. Short spans up to 200 meters retain the original 25-meter approach requirement and 95% endpoint-chord/length limit. Larger spans require 50 meters of selected approach at both ends and an endpoint chord at least 85% of span length. Up to 16 bridges are allowed. Moving, suspension, cable-stayed, arch and other unsupported structural types are rejected with specific UI reasons. Tunnels have separate eligibility checks below. Width and elevation checks can fail the background job after geographic data arrives.

Deck elevations interpolate between real elevation samples 20 meters outside short bridges or 50 meters outside large bridges, with the existing road smoothing and offsets retained. Grades above 12%, estimated clearance above 150 meters, or terrain above the estimated deck are rejected. Terrain under the span is protected from corridor filling; the MeshRoad supplies the collision deck, with generic collision guardrails and generated piers where clearance permits. These estimates do not reconstruct actual bridge engineering, stacked roads or water. The UI and ZIP report explicitly identify estimated bridges. Supported tunnels use the separate terrain-opening and collision-interior pipeline below.

Tests cover non-overlapping and crossing structures, unsupported tunnel rejection, simple/complex and length/approach checks, plus a synthetic valley export verifying deck height, unfilled terrain, supports, rails and report warnings. These are offline checks; real bridges still require in-game review. No existing ZIP is modified.

## Roadside scenery placement

Generic scenery is placed only within 200 feet (60.96 m) of the nearest selected road edge. The entire conservative circular object footprint must remain outside pavement and inside that limit; there is no extra roadside exclusion zone. Nearby bends and parallel sections are checked too. Structures intrinsic to the road, such as bridge supports and start/finish arches, are separate from scenery placement.

Candidates are generated along road length rather than across the map square. The target is 250 objects/km, bounded to 400–12,000 objects and at most 200,000 attempts. This is a performance budget, not a guaranteed count: water, steep slopes, overlapping footprints and map boundaries reject candidates. Generic trees, bushes, rocks and box buildings use aerial-color estimates; building footprints and individual vegetation are not reconstructed from authoritative data. The ZIP report records target, attempts, actual category counts and rejection counts. Regenerate old exports to apply this placement method.

## Stock vegetation, visibility and conservative buildings

New exports reference the installed BeamNG.drive 0.40 Utah Juniper_tree_01 and Juniper_bush_small_01 assets, using native Forest placements with their existing LODs/impostors. A generated mainLevel.lua pre-start hook loads stock juniper material definitions. No stock meshes or textures are copied into the exporter or generated ZIP. Stock Utah content must be present on the player's installation; the Debian server does not need BeamNG installed. Mesh paths and material references were checked against 0.40.4; rendering must still be validated in-game. Tree/bush footprint bounds were enlarged to match the referenced assets and retain the 200-foot scenery band.

LevelInfo explicitly sets visibleDistance to 16,000 meters with fog density 0.000015; user graphics/LOD settings can still limit rendering. Small generated props are not forced to full detail at all distances. Road elevation sampling remains 1024 and the original corridor method is retained, with terrain recess reduced from 0.60 m to 0.30 m. The road's 0.25 m elevation offset remains unchanged.

Buildings are no longer inferred from gray aerial pixels. Until mapped building footprints are imported, exports deliberately omit guessed buildings; rock and pavement colors are insufficient evidence of a roof. Counts and the building policy appear in the export report. This supersedes earlier color-based box-building behavior.

## Multi-map vegetation palette

Exports can reference stock vegetation from Utah (junipers), West Coast USA (small pines), East Coast USA (two small beech variants and bushes), and Johnson Valley (shrubs). Broad longitude/latitude, elevation and aerial-cover rules choose an approximate regional palette, with mixed variants and rotations. These rules are not a species survey. Asset-specific conservative footprints preserve the 200-foot roadside limit and avoid pavement/other objects.

Only used forest types and material libraries are emitted; shared material libraries are loaded once. The report lists the exact referenced assets and stock maps required on the player''s BeamNG.drive 0.40 installation. No game meshes, textures or material definitions are bundled. The server still needs no game installation. Regenerate to apply the palette; future game updates may require catalog path changes.

Optional read-only verification: php tests/beamng-assets.php PATH_TO_BEAMNG_INSTALL checks every catalog mesh and material file against installed stock level ZIPs. It neither copies assets nor modifies the game. Runtime material loading and appearance still require in-game verification.

## Mapped buildings, road tapers and terrain checks

BeamNG generation uses cached or newly requested OSM building ways in a bounded 90 m corridor through the configured OSM_OVERPASS_URL provider. Only closed convex footprints of 12–1,500 square meters with radius at most 25 m are eligible. Full footprint bounds must remain outside selected pavement and within the 200-foot roadside band, and corner elevation spread must be at most 1.5 m. Overlapping buildings are skipped; vegetation reserves accepted building footprints. Generic collision meshes follow footprint polygons; heights use mapped height or building:levels, otherwise an explicitly estimated 6 m default (clamped to 3–30 m). Building relations, holes, concave/complex footprints and large buildings are currently omitted.

Building retrieval is bounded to 1,000 ways, 50,000 vertices and 16 MiB. Partial/provider failures omit buildings with a report/UI warning; no color-based guesses are substituted. Downloads are temporary and discarded with other job source data. The building pass adds no database migration or persistent cache. Offline placement tests run by default; the existing disposable PostGIS integration suite now tests corridor SQL and reprojection with injected provider responses. Live building retrieval has not been verified in this development environment.

Lane-width changes use smooth tapers over 100 feet (30.48 m) on each side. Overlapping transitions blend; taper sections use simplified edge-only markings rather than fabricated engineered merge lanes. Terrain base imagery receives a 1.2 saturation factor without changing raw colors used for placement/classification. A post-shaping pass samples the road ribbon and lowers contributing terrain-cell vertices where they exceed the conservative road envelope, leaving at least 8 cm numerical clearance; it does not fill bridge valleys. The report records corrections, maximum cut, taper distance and saturation factor. The pass checks sampled geometry rather than guaranteeing every renderer LOD/Catmull-Rom interpolation is intersection-free; in-game review remains necessary.

Vegetation remains stock-only Forest instances, with no generated plant meshes or silent procedural fallback. The map pre-start hook now checks required shape and material references and displays an in-game warning if missing. Polygonal close-up appearance in an affected ZIP still needs investigation; successful path/package checks do not prove runtime material or LOD correctness.

Stock vegetation also depends on each source map''s parent art/shapes/trees/main.materials.json library, not just the species folder. New exports load these shared libraries first to resolve leaves_strong/leaves_thin mappings and list all required material libraries in the report. The optional installed-asset test now checks every material named by each stock DAE against the loaded libraries, catching missing dependencies even when mesh and material files exist. This addresses the missing mappings observed for the supplied Mount Rose export; visual confirmation remains an in-game check. Existing supplied ZIPs are read-only reference files and are not modified.

Trees, bushes and scatter rocks now all reference installed stock meshes through the native Forest system. Scatter rocks use Utah utah_boulder_1, with conservative measured footprint bounds. Exports no longer bundle procedural rock/tree/bush placeholder meshes. Arches, bridge parts and mapped building extrusions remain intentionally generated. The report''s stock_scenery_assets field identifies exact model dependencies; the older vegetation_assets field remains for compatibility. Fresh regeneration is required; supplied diagnostic ZIPs are never modified.

Terrain color saturation now uses a centralized 1.5 multiplier. The corridor recess is reduced to 10 cm using the same shaping method; original 1024 elevation sampling and the road elevation offset are unchanged. The overlap-removal pass remains active with its 8 cm numerical clearance, so intersecting terrain cells can still be lowered further when necessary. Generate a fresh export to apply these settings.

New BeamNG exports start at 7 AM with time progression disabled. The scene uses the engine''s noon-based normalized clock value 19/24. Players can still change the time in-game; regenerate older ZIPs to update their default.

## General mountain vegetation inference

Vegetation placement now combines a broad regional/elevation prior with nine neighboring raw aerial-color samples, rather than requiring a single bright-green pixel before any tree can spawn. Shaded or muted canopy can support trees; coherent strongly blue neighborhoods remain excluded as water. Western montane settings increase tree probability and favor the installed stock pine model. Bright neutral bare/snow-like terrain suppresses trees, and a latitude-adjusted high-elevation fade prevents the heuristic from adding forests indefinitely uphill.

These are visual heuristics, not measured species distributions, climate zones or authoritative land-cover data. No road name, ZIP or locality is special-cased. The report records inferred biome counts, actual asset counts and the inference method so future exports can be assessed. Density budgets, footprint/road checks and 200-foot limits remain in force; validated source downloads may be reused for up to seven days. Authoritative canopy/land-cover datasets are a future improvement; stock pines are appearance proxies rather than claims of exact local species.

## Stock terrain materials (experimental)

BeamNG exports use stock terrain materials blended with aerial imagery. Job restoration and errors remain scoped to the selected road name and direction. Exports reuse validated source imagery/elevation for up to seven days; stock terrain still requires those inputs.

Stock mode references five PBR surfaces already supplied with BeamNG.drive 0.40: grass, forest floor, dry soil, gravel and rocky ground. Each uses stock albedo, normal, roughness, AO and height textures from the shared assets/materials/terrain archive. All were verified at 1024-square dimensions against the installed game. The map references these textures without copying them; the server does not need the game installed. Texture repetition is expressed in terrain-grid units, approximately 8 m per repeat (rounded to at least one grid cell). No extra geometry displacement is added to collision terrain.

Classification averages neighboring raw aerial pixels and considers slope plus the existing regional/elevation vegetation heuristic. A majority filter suppresses isolated material speckles, and BeamNG blends adjacent terrain layers. Ambiguous flat gray, blue/water-like and bright snow-like patches retain aerial imagery; the exporter does not invent water or snow geometry. Mapped roof samples are marked for fallback rather than interpreted as stone. Classification uses the full downloaded imagery/terrain resolution (normally 2048 square), with a small isolated-speckle filter. Boundaries remain heuristic rather than per-object reconstruction.

Five stock layers plus a sixth aerial-fallback layer share a 1024-square base texture array; stock mode downsamples the aerial fallback to match that array. Aerial mode retains the previous full-resolution aerial base. Classification uses the original imagery, while saturation boosting applies to rendered aerial textures only. Stock texture channels are not color-edited or redistributed. The export report records the selected style, category counts, analysis resolution and required texture paths; game startup diagnostics check those paths. Use Aerial imagery if classification or stock rendering looks unsuitable.

Tests cover class decisions, uncertain-area fallback, stock package layers, texture dimensions/paths and frontend style selection. Stock rendering and material transitions still need in-game visual/performance review. Terrain-style selection requires no new migration or deployment packages. Existing ZIPs remain unchanged; deploy and generate a fresh export.

Stock terrain no longer enlarges a coarse 256-square material map. Every downloaded image pixel receives a material classification at the matching terrain-grid resolution. Neighbor sampling spans one source pixel, and the 3-by-3 filter only replaces isolated outliers, preserving thin features and boundaries. The ZIP report includes analysis resolution and ground spacing per classified pixel. A 2048 image over an 18.46 km map still represents roughly 9 m per pixel; this change removes the extra eightfold enlargement, not that inherent imagery resolution. Processing costs more CPU but stays in the cancellable background worker with bounded 2048 resolution.

## Revised stock terrain palette

The web export control now always requests Stock materials; its terrain-style dropdown and saved Aerial preference are removed. Automatic aerial fallback remains for genuinely ambiguous areas. The aerial API mode is retained for compatibility/testing, not exposed as a web control.

Seven physical terrain classes are now supported: grass, forest floor, dry soil, gravel, stone, rock and sand, plus aerial fallback. Warm pale terrain can classify as sand, pale or shaded neutral mineral slopes as stone/gravel, and steep slopes as rock. Bright near-neutral snow-like colors and blue water-like colors retain fallback. Flat uniform gray areas remain uncertain to avoid turning pavement into rock; mapped building bounds are also preserved as imagery.

Palette changes replace grass 01 with grass 02, the moss-heavy forest floor with dry grassy ground, and dark loose soil with crumbly soil. Stone uses stock pebbles and sand uses stock sand. Matching albedo/normal/roughness/AO/height channels are referenced from the installed game; no stock image data is included in generated ZIPs. These are visual proxies, not geological or land-cover measurements. Full-resolution classification, the isolated-speckle filter, 200-foot scenery bounds and terrain-overlap correction remain unchanged. Regenerate an export for the new palette and review appearance in-game.

## Terrain correction after export (15)

Vegetation color evidence is evaluated before slope-based mineral classification, including muted blue-green forest shadows. A steep hillside alone is no longer enough to replace a vegetated patch with rock. Neutral gray mineral surfaces retain the stone/gravel rules; these remain visual heuristics rather than surveyed land cover.

The forest-floor slot now uses stock `grass/ind_grass/t_ind_grass` (grass blades rather than the stony `soil/t_dirt_dry_grassy`), dry soil uses `soil/t_dirt_sandy/t_dirt_sandy`, and exposed rock uses `rock/terrain_dirt_rocky_large/t_dirt_rocks_large`. These supersede the earlier palette choices above. All five PBR channels follow each replacement; no game textures are copied into exports. ZIP (15) confirmed that soil occupied under 0.1% of the map, so changing only its texture could not fix dark areas belonging to other layers. Regenerate an export to apply the correction; lighting and appearance still require in-game validation.

## Stock material rendering correction (export 16)

Stock terrain textures are now used as PBR **detail** layers over generated per-category base colors, matching the layout used by bundled v0.40 levels. The previous exports incorrectly used neutral detail textures directly as the base color, which made vegetation appear gray/brown even where the classification selected grass. The v0.40 shader adds `(2 * detail - 1) * strength` to the base color; color detail strength is 0.18, with explicit green vegetation and lighter warm soil base colors. Mineral layers also have explicit lighter base colors. Classification rules are unchanged by this rendering fix.

All base/detail array images are 1024 square, including the aerial fallback. Stock detail retains its original resolution rather than being reduced to the old 64-square detail array. Normal, roughness, AO and height channels follow the detail layer; macro contribution is disabled. Stock textures remain game references and are never bundled. The report includes `terrain_material_method`. Shader-formula and installed-texture color tests verify the material setup; final lighting still needs an in-game check. Existing archives are unchanged.

Vegetation close-up correction: grass and forest-floor color detail now use strength 0.02 (other stock categories retain 0.18), with normal detail 0.25 and AO detail 0.04. This bounds the stock detail tint so it cannot override the green base as detail appears nearby. All stock height-detail strengths are zero to prevent distance-dependent material boundary changes. Road/terrain elevation and collision geometry are unchanged. Regenerate to apply; in-game lighting can still affect perceived colors.

## Blended aerial colors for stock terrain

Stock material base maps now blend their palette with locally filtered aerial colors. Exposure variation is capped at 25 channel levels, color tint at 23.4, and each channel stays above 85% of its palette value. Vegetation keeps at least 16 levels of green-channel separation so the low-strength close-up detail cannot turn it brown. Near-black, bright neutral snow-like and strongly blue water-like samples retain the palette. These are visual safeguards, not authoritative land-cover detection. A five-sample filter softens photographic noise; it does not remove every shadow or rooftop.

The north-up 1024-square tint field is calculated once and reused across material layers. Classification, stock PBR details, physical surface types, and road/terrain geometry stay unchanged. Aerial fallback still uses the imagery. The worker reports blending progress and retains cancellation checks; no extra provider request is required beyond the existing export imagery download. Regenerate to apply. Appearance still requires in-game validation.

BeamNG preparation shows a nine-segment stage bar beside the existing worker status: queued, elevation, aerial imagery, preparation, terrain analysis, road shaping, materials, scenery and packaging. Orange marks the current stage and blue marks completed stages. Stages are inferred from reported worker messages on each status poll, including resumed jobs; they do not represent percentages or time remaining. Failure/cancellation hides the active bar while retaining its status message; completion fills the bar and exposes the download.

## Road shoulders and bridge exclusion

Ordinary BeamNG road sections now have a generic dirt/gravel roadbed surface 5 cm below pavement and two sloped shoulder ribbons. Each ribbon begins just below the pavement edge and meets the final shaped terrain, widening from 1.5 to at most 6 meters to soften larger drops. The original road elevation sampling and road height are unchanged. Corridor shaping and clipping correction target 5 cm clearance. The supporting mesh provides a precise nearby ground surface within the requested 10 cm; the underlying coarse elevation grid can still be farther below the pavement on grades or overlapping cells. This is estimated shoulder/backfill geometry, not surveyed shoulder construction; extreme terrain can still produce steep joins and needs in-game review.

Bridge protection is shared by corridor shaping, terrain-intersection correction and shoulder generation. No supporting roadbed/shoulder ribbons are generated in protected bridge areas, and the clipping pass no longer lowers protected terrain beneath a deck. Protection is conservatively expanded around bridge samples, so shoulder strips can stop before the exact abutment. New report field shoulder_transition records generated clearance, width bounds and maximum drop. Regenerate exports to apply.

Shoulder correction: shoulder and roadbed collision materials now use the underlying terrain category's ground model, rather than DIRT on every strip. Left and right edges are sampled independently and strips split when categories change. Their simple visual textures use the matching stock terrain palette color; they do not reproduce the terrain shader exactly. Outer edges extend another 0.75 m (minimum total width 2.25 m, maximum 6.75 m) and finish 0.15 m below the sampled final terrain to overlap and hide seams. Bridge checks use these extended endpoints too. Pavement and the 5 cm supporting roadbed height are unchanged. Actual tire/collision behavior and joins on irregular ground still need in-game verification.

Region cancellation is cooperative: the request marks its task and releases the area key immediately; the worker stops at its next checkpoint. Cleanup avoids running imports and skips busy rows instead of blocking the cancellation request or Manage refresh. Completed/active datasets remain protected. Unexpected API failures now record exception class, source filename/line and (for PDO errors) SQLSTATE in php-error.log. They do not log SQL, parameters, request bodies or exception messages. SQLSTATE 55P03 indicates a lock timeout, which helps distinguish contention from schema/constraint errors. The lock-regression integration test requires two connections to a disposable PostgreSQL/PostGIS database.

Custom selections now request one tight axis-aligned rectangle around their two points instead of radius-search half-degree tiles. Padding is 25% of endpoint distance, bounded between 1 and 5 miles, plus a 0.002-degree import halo. Stable 0.001-degree boundaries and direction-independent keys reuse equivalent requests. Existing fresh coverage skips the download when it covers the whole rectangle; a partially covered rectangle may still download overlapping data to preserve one continuous extract. Dense rectangles can subdivide with the same small halo. The padded rectangle accommodates winding roads, but extreme detours can still leave it; the importer does not invent connections outside downloaded coverage. Regular ZIP/radius planning is unchanged. Existing queued jobs are not cancelled by this change.

Shoulder collision correction: shoulder and support strips are now open, top-only COLLADA meshes loaded as TSStatic with Visible Mesh Final collision. They contain no solid ribbon side walls, underside faces or end caps. Triangle winding is upward, and material changes share precomputed boundary rail coordinates so they do not introduce end walls or mismatched seams. Physical ground models still match terrain categories; road elevation, bridge protection and outer-edge embed remain unchanged. Tests verify triangle counts, upward normals, boundary agreement and exported collision objects. This removes a structural collision hazard; actual driving/tire behavior must still be validated in-game using a freshly generated ZIP.

## Native-terrain shoulders (current approach)

This replaces the separate shoulder/support meshes described above. Exports now contain no shoulder TSStatic objects, MeshRoad ribbons, shoulder collision meshes or shoulder-specific materials. Only the actual pavement remains a MeshRoad. Native terrain is raised or lowered toward a target 5 cm below the nearest road segment, with interpolated road grade and width. Beyond a grid-aware inner margin, a smoothstep falloff blends into the unchanged source terrain over at least 6 meters or three terrain cells. Height blending always reads the original terrain rather than accumulating previous changes.

The bridge protection mask excludes both terrain blending and the existing intersection-clearance pass. Road elevation sampling, native terrain materials and selected-road orientation remain unchanged. The report's shoulder_transition describes the terrain-only method and changed vertices. A coarse grid can still prevent a strict 10 cm clearance everywhere on grades, tight bends or nearby road sections at different heights; this approach favors a continuous native ground collision surface over precise separate shoulder geometry. Fresh exports and in-game validation are required.

Native shoulder correction after ZIP (24): the terrain-intersection pass now evaluates interpolated height at road contact samples instead of assigning every corner of a terrain cell the lowest sampled road height. It checks bilinear interpolation and both possible triangle diagonals, lowering only enough to resolve excess height with weighted vertex adjustments. This preserves an already-correct road grade. Bridge cells remain protected. The 5 cm target is unchanged; bends and conflicting nearby heights can still require additional cuts. Regression coverage includes a 10% grade at ZIP (24)'s 3.5207-meter terrain spacing.

Bridge-abutment exception: the broad bridge safety mask can cover land beyond a bridge and prevent ordinary terrain shaping there. A second pass now permits only landward vertices near mapped bridge ends (within 25 m or four terrain cells, whichever is larger), protecting vertices projected inside the deck span with a 0.5 m boundary margin. It blends those landing areas to the road and corrects contact heights using only editable corners of mixed cells. Ordinary-road shaping and its default clipping behavior are unchanged. No approach pass runs for exports without bridges. Deck-interior terrain vertices remain unchanged; interpolation in cells spanning the land/deck boundary can change at the abutment. The report records bridge_approach_correction and its local shaping statistics. Fresh exports and in-game verification are required.

Bridge-side ridge correction: elevated bridge segments are now excluded as height targets from both ordinary and approach terrain blending. The bridge protection radius covers the complete shoulder inner margin/falloff plus a terrain-cell guard, rather than only two cells. This prevents terrain outside the old narrow mask from being pulled toward deck height. The landward approach exception uses the matching influence width and still protects deck-interior vertices. Ordinary non-bridge shoulder output is unchanged. Previously generated ridges are baked into those archives; regenerate to apply the fix. Tests reproduce the old ridge in a synthetic valley and verify the corrected bridge leaves that valley unchanged.


Discovery sidebar tabs: **ZIP search** contains radius and advanced filters; **Custom road** provides the two-point picker; **Your Discoveries** contains road diagnostics followed by results. The driving profile belongs to ZIP search; custom selections use the currently selected profile. Staged preparation status stays visible below the active panel. Completed searches automatically open Your Discoveries, including searches with no matches. Switching tabs preserves form values and does not cancel preparation. Use arrow keys or Home/End while focused on a tab to change panels.


Terrain color refinement: stock base colors now move 50% toward raw aerial hue/chroma after matching the photo's mean brightness to the existing bounded exposure. This reduces the forced palette appearance without importing deep photographic shadows. Black, snow-like and blue water-like samples retain their palette safeguard. Aerial fallback saturation is 1.25 rather than 1.5. Regenerate exports to apply; geometry and material classification are unchanged.

Building diagnostics: BeamNG downloads OSM building ways separately within a 90-metre corridor of the selected road; it does not infer buildings from photographs.

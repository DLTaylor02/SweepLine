# Architectural decisions

## 1. Preserve the deployment contract

Adapt the supplied installer rather than replace it. Keep its configuration, helper functions, project hooks, rsync exclusions, non-login user, FPM socket, NGINX template, service checks, and systemd hardening. Extend it with resource ownership checks, version-specific PHP/PostGIS package selection, migrations, HTTP health verification, and NGINX configuration rollback. Database provisioning is deliberately limited to the local default cluster so an environment override cannot silently target a different cluster. Existing marked deployments use their deployed credentials.

## 2. Bounded local ingestion

Automatic Overpass jobs return bounded complete-way XML for ingestion through PHP XMLReader. Optional developer PBF imports use Osmium to produce the same XML format. This avoids a persistent ingestion runtime and allows a small Overpass development extract using the identical importer. Nodes persist per import; relevant ways are normalized and indexed. The graph stage is bounded and memory-resident, rather than pretending to scale to the entire country. Extend regions now; move graph partitioning/preprocessing into SQL or a dedicated offline pipeline if scale requires it.

References: [Osmium cat](https://docs.osmcode.org/osmium/latest/osmium-cat.html), [Geofabrik regional extracts](https://download.geofabrik.de/). Automatic cells derive coverage from their fixed request bounds; optional local imports declare coverage explicitly; source hashes and activation timestamps are recorded. No external calls occur for geographic searches.

## 3. Atomic dataset visibility

Import jobs own every node, segment, connectivity row, candidate, and score. Only `regions.active_job_id` makes a completed job visible. Validate the extract and generated candidates before activation; verified empty automatic extracts may activate empty coverage. Keep previous jobs for rollback/diagnosis. A session advisory lock permits one importer, while queued jobs are claimed under row locks. A dead worker's running jobs are failed, not resumed from partially committed batches. This favors correctness over resumability. Automatic data tasks retry or subdivide interrupted/failed work, refresh stale searched coverage, and prune nonactive automatic import attempts after a week. SuperAdmin can retry terminal failures in the web UI.

## 4. Continuous stretches rather than OSM way results

Split ways at shared nodes. Extend each edge at both ends when exactly one matching identity/class/direction continuation turns less than 55 degrees. Prefer `ref` over name, using case-normalized strings. Stop at ambiguity; do not invent a turn through a fork. A visited-edge set prevents cycles and double assignment. Chains target a maximum of about 40 km, allow a final edge up to 50 km, and retain long single ways intact. Short candidates under 400 m are discarded. OSM way boundaries with only two distinct neighbors do not increase intersection counts. Actual junctions penalize continuity but do not automatically imply stops. Identity changes and unresolved directional transitions break candidates.

## 5. Geometry and quality

Haversine lengths and local bearings support uniformly resampled geometry (30 m). The qualifying curve radius band is 40–600 m; sharp changes >=55 degrees are excluded. Curve quality blends weighted curvature, sustained sample runs, and length. Mapping jitter and urban right-angle grids cannot create arbitrary scores from dense points. This heuristic needs calibration against real enthusiast judgments; it is not a vehicle-dynamics model. Database radius queries use spheroidal PostGIS geography, with a matching GiST index: [ST_DWithin documentation](https://postgis.net/docs/ST_DWithin.html).

Dimensions are normalized 0–1; weights are centralized, sum to 1, and yield 0–100 scores. Known missing attributes receive conservative values. A separate completeness value reflects attribute availability, and a modest score factor avoids missing attributes winning by default. Completeness has a structural base for valid topology and is not a statistical confidence interval. Mandatory control counts include unconditional traffic signals along an unshared segment and explicit all-way stops; shared/directional signals, ordinary stops, and barriers remain uncertain. A side-approach node is counted only if that node actually lies on the candidate. Signal counts mean potential interruptions, not a claim the signal is always red. Missing controls can never be detected from OSM alone.

## 6. Elevation deferred honestly

Gain/loss/max-grade fields are nullable, omitted from profile weights, and displayed as unavailable. A future preprocessing stage can sample USGS 3DEP DEM tiles at 20–30 m spacing, interpolate heights in a compatible vertical datum, smooth noise before computing grade/gain/loss, and store source/version/sample spacing. This avoids querying elevation APIs per search or misleading users with noisy OSM `ele` tags. Recompute cached scores only after validating a real elevation source.

## 7. Bounded read API and map

Web requests never import or score roads. Radius must be a whole number from 1 to 50 miles, results at 100, geometries simplified for map transport, request bodies limited, and SQL/web execution time bounded. Whole candidate metrics are returned for roads intersecting the radius, rather than misleadingly claiming the whole road lies inside it. Coverage compares the search circle with the union of declared active polygons. MapLibre uses a replaceable raster basemap; all dynamic road labels use DOM text rather than HTML insertion.

## 8. Installation bootstrap and web-managed data

The sole installer entry point is `sudo ./setup.sh`; all system provisioning remains in the established installer template. The default port prompt uses 1279 for a fresh install and preserves an existing port on upgrades. The non-login Linux user is a service identity, independent of application accounts.

Migrations 002/003 add hashed-password users, usernames, optional email addresses, login attempt counters, settings and a persistent data queue. The installer checks for an existing SuperAdmin, prompts for and confirms a hidden password only if missing, and passes the secret to its PHP CLI helper over standard input. Account creation serializes under a table lock; existing credentials are never reset. Browser account claiming is removed. Upgrades add usernames while preserving account/password data and legacy email login. Session IDs regenerate on login; cookies are HttpOnly/SameSite, mutations require CSRF, and account changes invalidate sessions via version counters. Only SuperAdmin/member capabilities are defined pending permission design.

The installer queues GeoNames initialization. Searches queue absent/stale half-degree OSM cells, with smaller cells for dense areas and a short continuity halo. Precomputed canonical geometry keys deduplicate identical whole-way candidates across cells without dropping roads whose midpoint lies beyond the requested area. Cross-cell fragmented candidates still need future stitching. Bounding boxes plan acquisition; search distance remains PostGIS geography. Valid empty OSM data is coverage rather than an endless import failure.

The PHP worker downloads and extracts ZIP coordinates, fetches OSM, and delegates local analysis to the established importer. Cached data, retry backoff, restart recovery/subdivision, provider quotas and resource guards bound shared-host work. Failed refreshes retain active datasets. The web UI polls preparation status and exposes failed-job retries to SuperAdmin. Normal operation needs no command-line imports; those tools remain optional developer diagnostics. Source availability still constrains cold searches, so the UI shows real progress/errors rather than invented results.

Job cancellation is persistent and cooperative. Migration 004 adds cancellation flags and a cancelled preparation-task state. The worker checks requests during network progress and importer loops; final activation checks lock the task and import rows in the activation transaction to serialize cancellation with publication. Queued tasks are cancelled immediately; running tasks acknowledge cancellation at a checkpoint. Cancellation applies to the current attempt; later demand may recreate a fresh job. Cancellation preserves previously active data; partial inactive attempts remain eligible for normal maintenance. `/jobs` uses the same session and SuperAdmin API authorization as management.

Dedicated `/manage`, `/jobs`, and `/history` pages share the shell and session handling. Manage fetches user records only; Jobs fetches background preparation information only. Migration 005 adds per-user search history with an index on user/id. Explicit initial browser searches record normalized filters; polling does not. History uses authenticated user IDs rather than client-supplied ownership, serializes writes per user, suppresses duplicate submissions within ten seconds, and retains at most 100 entries per account. Rerunning restores parameters without replaying stale results. The default radius is 5 miles.

Migration 006 originally retained cancellation keys; migration 007 removes that suppression table so future demand can create fresh jobs. Cancellation deletes queued/retrying entries immediately, excludes pending running cancellations from job lists/counts, and removes running rows after acknowledgement or restart recovery. Running cancelled attempts temporarily use a cancellation key based on their ID to free the original unique area key. No persistent cancellation marker remains after cleanup. Cancelled inactive imports and their partial geometry are removed after processing stops; active regions are never deleted. This supersedes the earlier retry-cancelled-task behavior.

Migration 008 introduces account-owned favorites, unique by canonical geometry key and driving profile. Snapshots contain server-owned candidate geometry, metrics, scores and ordered OSM parts plus validated search parameters; there is deliberately no candidate FK because imported IDs are ephemeral. Lists simplify snapshot geometry for SVG thumbnails; detail/export retains the saved full geometry. Capacity is bounded to 200 favorites per user under a user-row lock. Saved roads open as a single highlighted map result and do not enqueue new imports or rely on old candidate IDs. Favoriting an inactive road anew requires discovering a current candidate; existing saved snapshots remain viewable/exportable.

Road exports derive mileage and road-shape notes from the oriented candidate track, never by summing original member way geometries: a candidate can contain multiple fragments of one way, while candidate_segments references the full source geometry. RoadNotes uses 15 m sampling, approximately 60 m chord headings, a 0.5-degree per-step dead band, same-direction bend grouping with up to 45 m of quiet geometry, a 15-degree minimum net bend and 5-degree output rounding. Signs follow clockwise/right versus counterclockwise/left; reverse-direction bends split groups. Distances are cumulative from track start and bounded by the track length. Notes are map-derived approximations, not surveyed pace notes or navigational junction maneuvers.

Styled PDFs are rendered by RoadPdf with built-in Helvetica regular/bold/oblique fonts, vector left/right/hairpin/start/end icons and paginated note tables. ExportMap queries spatially indexed active road segments in a padded Web Mercator viewport (up to 1,200 segments), adding a real local street basemap with road names, north marker and scale. Track and background share one projection. New favorite snapshots retain this map context; older snapshots load current local context when available. No raster tile downloading, external rendering runtime, or new Debian dependency is required. The map omits land-use/terrain/building data because those features are not imported.

Twisty eligibility is separate from weighted quality: search SQL applies the centralized profile eligibility thresholds to stored geometry metrics before ranking/limiting. Missing metrics fail qualification; road class is not an exclusion. Curvature carries 70% of Twisty quality. Installer-driven rescore updates existing road_scores from their stored dimensions when the profile definition changes, using a transaction/advisory lock; geometry is not imported again. Generic import/length tests explicitly use Open Highways so geometry qualification is tested independently rather than implicitly waived for synthetic straight fixtures.

RoadDiagnostics is a read-only authenticated/CSRF-protected endpoint using the exact validated discovery filters and active local imports. It searches candidates and member-way aliases before evaluating each failed requirement, compares against actual returned results, and separately shows raw imported source tags. Source-way spatial matching uses the geometry index plus true geographic distance. Results are capped at 100 per category; the report distinguishes missing local data from rejected candidates and does not schedule imports or alter thresholds.

Normalized advanced filters use a 1–10 linear density score (1 + 9 × raw/53.6448), default 2.2, with legacy raw-density conversion. Search and diagnosis share the same validated density, curvature-quality and sustained-curve thresholds. Surface class is separate from inclusion policy: migration 009 and Surface classify candidates as paved/unknown/unpaved, with explicitly unpaved pieces taking precedence over unknown pieces. The default policy admits unknown surfaces while rejecting known unpaved; legacy paved_only retains its original strict/all meaning. Migration backfills stored metrics and confidence, and the installer's rescore step updates quality scores without downloading road data. Saved Favorites retain their historical geometry/metrics; displays normalize density on read.


BeamNG export uses a separate owner-scoped beamng_exports table and the existing single CLI worker. Geometry is resolved server-side from current candidates or owned Favorite snapshots, projected to local UTM, and bounded before enqueueing. GDAL normalizes real USGS rasters; a native PHP writer emits terrain v9, generated textures/COLLADA, MeshRoads and two SpawnSpheres in a self-contained level ZIP. No game assets or extra daemon are required. The separate cleanup cron expires private downloads after 30 minutes even while the worker is busy. Coverage, structures and size restrictions fail explicitly. Synthetic format tests and read-only comparison against BeamNG 0.40.4 do not replace a live-provider and in-game acceptance test.

BeamStructures identifies tagged structures by collinear overlap in projected meters against the selected line; it does not apply whole-way tags to unrelated selected fragments. Bounded eligible bridge spans receive approach-derived elevation samples before ordinary smoothing. The terrain corridor writer protects cells beneath these spans, while the MeshRoad remains the collision deck and generated rails/piers supply generic structure. Plan/job/report warnings identify estimates. Complex bridges and unsupported tunnel types fail explicitly; ordinary tunnel=yes spans use the separate BeamTunnels pipeline. Structure evaluation does not add external requests or change ordinary-road elevation sampling.

BeamScenery samples candidates by road chainage and lateral offset, using a 64 m spatial segment index for footprint-to-road checks. Terrain resolution does not control scenery clearance. Circle bounds conservatively cover each generated mesh; accepted footprints must stay off all nearby pavement and wholly within the 200-foot road-edge band. A separate occupancy grid prevents object overlap. Counts and bounded rejection statistics accompany each ZIP.

BeamTerrain performs bounded coarse-grid image/slope classification before corridor shaping. It emits six native terrain layer indices: five stock PBR materials and aerial fallback. Stock albedo/normal/roughness/AO/height references use matching 1024 texture slots; fallback imagery is resized to that array size, while terrain geometry remains independent at 2048. Aerial mode retains its existing path. Source imagery stays unchanged for vegetation analysis. Classification is heuristic and uncertainty favors fallback. Terrain style is validated in BeamPlan and serialized into the job fingerprint/report.

## Custom two-point selections

CustomRoads validates two geographic clicks against one active, simple continuous candidate, snaps and clips with PostGIS, then requests fresh geometry/control scoring through RoadConsolidator. It does not use client-supplied paths, invent junction routes, or interpolate across gaps. Cache keys include clipped coordinates when recalculation is requested. Synthetic clip endpoints do not increase unknown-control counts.

The custom_roads migration stores private bounded snapshots by user. Custom API reads, exports, favorite saves and BeamNG jobs independently enforce ownership. Source geometry for lane/structure analysis is clipped to a narrow buffer of the selected line. The original full candidate is never replayed as the export track. Favorites copy an independent snapshot; logical selection expiry cannot remove saved geometry. Custom coordinate preparation reuses DataQueue and existing fresh coverage, otherwise downloading a tight endpoint rectangle with bounded padding and a small halo. Radius searches retain their normal reusable tiles.


BeamNG maps with intersections use an explicit top-only primary ribbon and clipped side-road/connector meshes. The original sampled centreline, elevations and width profiles are retained, while cross-section edges are computed once and interpolated for paint boundaries. Side-road triangles inside the primary footprint are removed, and contact vertices inherit exact primary edge heights. This supersedes native primary MeshRoad rendering for junction maps: BeamNG's independent Catmull-Rom interpolation cannot share a guaranteed collision boundary with a separately generated connector (https://documentation.beamng.com/modding/levels/level_classes/meshroad/). Maps without side-road geometry retain their previous native renderer. This intentionally changes surface interpolation on junction maps, rather than pretending linear connectors can exactly match the engine spline. No source route points or sampled elevations are changed. Primary top-only collision has no overlapping caps/sidewalls at junction mouths; native traffic/minimap graphs remain separate.

BeamJunctionBoundary clips convex pieces against nearby primary ribbon triangles, preserves boundary-coincident vertices on both clipping halves, interpolates lane UVs and rejects degenerate triangles. Exact edge ray intersections are limited to 50 metres along the original junction neighborhood; clipping also removes any incidental primary overlap elsewhere on a branch. Paint-boundary subdivisions retain existing edge positions instead of recalculating their normals. Each branch and connector remains one indexed mesh. Native terrain shoulders and bridge protection retain their existing passes; they are not replaced with collision shoulder objects. In-game tire/collision validation remains necessary.

Mapped-building placement uses polygon tests and concave roof triangulation. The 200-foot corridor remains a coverage rule, while circle-based road/neighbor exclusion and convex-only eligibility were removed. Rejection reason counts are retained in export reports so future adjustments can be based on actual exclusions.


Mapped guardrails: BeamGuardrails fetches only explicit OSM barrier=guard_rail ways in the selected primary-road corridor. PostGIS builds the bounded WGS84 query polygon and transforms returned lines into local UTM/map coordinates using parameterized queries. BeamOsm centralizes the existing 16 MiB, three-attempt, cancellation-aware context-download behavior shared with buildings. Provider errors are optional-context warnings and appear through the existing export status response.

Guardrail preparation joins degree-two compatible endpoints, removes duplicate geometries, streams samples under a 4,000-point budget and checks actual padded segment footprints against primary/side pavement. Horizontal locations are not shifted to compensate for mapping errors. Geometry uses terrain/pavement-relative estimated heights; unsupported portions are split/skipped with reason counts. Estimated bridge rails retain priority to avoid stacked barriers. BeamAssets serializes closed beam faces, posts and generic rigid terminal blocks as metal TSStatic collision meshes. Run ends include ends introduced by placement exclusions; terminals are not surveyed or crash-rated models. No guardrail locations are inferred from slope or imagery. Source coverage/provenance and placement outcomes are recorded in guardrail_data; raw inputs use the existing temporary job lifecycle.


Building appearance uses BeamBuildingStyle with explicit mapped building/use tags first, containing simple land-use polygons second, and a neutral fallback. Land-use hints are bounded (500 ways, 20,000 vertices, 16 MiB) and fetched independently so a failure cannot discard building footprints. They are heuristic land-use evidence, not legal zoning. The generic mesh writer supports face-material groups and per-corner UVs with flat wall normals; facade UVs repeat every 4 m horizontally / 3 m vertically. Roofs are a separate material. Stock DDS references are validated against the installed tileable asset archive and are not copied.

Road width profiles distinguish carriageway_width_m from width_m (total pavement), with shoulder_m=0.6096 on each side. Shoulders are added once after primary tapering and before branch preparation. Paint material keys include their quantized shoulder pixel margin to prevent mismatched textures at width changes. Spawn offsets use carriageway width. Terrain, primary/branch boundary clipping, object exclusions, bridge edges and guardrail placement use total pavement width.

BeamCurve rounds minor source corners with short quadratic segments, limiting deviation to 0.70 m and angle sampling to roughly 3 degrees. It preserves endpoints, sharp corners, junction anchor neighborhoods (20 m) and structure corridors (25 m). Rounding precedes lane/elevation sampling and side-road preparation. Fine segments are preserved by the road sampler instead of being discarded by its legacy half-metre cutoff. Rounded maps use explicit primary pavement; native MeshRoad remains only where neither rounded geometry nor side-road joins require explicit shared surfaces. New curve points intentionally supersede the earlier promise of an entirely unchanged source centreline, within the documented bound. This is not measured banking/engineering. Curve and point budgets remain bounded.

Facade detail generation retains mapped footprint meshes and adds capped-budget decorative quads for frames, glazing, doors and cornice/plinth trim. Appearance variants are deterministic from projected building locations, with bounded material reuse, stock normal/specular channels and opaque glazing over solid walls; there are no reconstructed interiors or surveyed openings. Bigger curve rounds use twice the prior trim limits and deviation allowance; protected-zone checks include the full trim footprint. Guardrail fetch outcome is explicit and separate from placement/coverage.


Secondary terrain correction now uses a primaryContactMask covering pavement plus the full grid-cell interpolation halo, consistently during both initial branch shaping and final contact correction. Previously final branch cleanup used only the bridge mask and could lower the very grid vertices supporting the main road. Primary clearance still uses its own bridge protections. Branch-only partial-cell adjustments have a 0.5 m per-vertex/per-pass budget; persistent conflicts shorten/omit context roads and discard stale turnarounds, with counts/warnings. The main top surface and elevations are unchanged.

BeamPavement derives external mesh edges and exports 18 cm fascia separately from the top collision mesh. BeamMap always assigns fascia collisionType=None and removes fascia XML from report payloads. This is visible road thickness, not collision shoulder geometry. T-junction side flags are relative to main-road direction; markingSections retains the unopened edge and merges opposing openings. Texture keys include kept-edge flags to prevent incorrect paint-material reuse.


BeamCompute provides a bounded proc_open process pool for CPU-only export tasks. New PHP CLI processes avoid inherited PDO connections and shared ZIP handles. Private flat job-workspace files hold serialized arrays (unserialize allowed_classes=false), including the raster's original elevation sampling source. Helpers produce raw row strips or PNG bytes; the parent orders results, applies building masks and owns all archive writes. Classification and neighbor-filter strips read complete input arrays, preserving border behavior and output bytes. Texture rendering is shared by serial/parallel execution paths.

Capacity is constrained by detected affinity, current/ancestor cgroup v2 quotas, MemAvailable and cgroup memory headroom, plus a four-helper automatic cap and one reserved CPU. A 512 MiB reserve/256 MiB per-child budget guards shared-host memory use. The application-only BEAMNG_CPU_WORKERS setting permits serial mode or a requested 2-16 helpers, subject to those resource bounds. Helpers lower their scheduling priority where available. No global PHP/system settings or additional service are introduced.

Parent checkpoints continue polling export cancellation/worker heartbeat during CPU batches. Direct array process arguments bypass the shell. Helpers have a 256 MiB PHP memory limit and a 600-second parent-enforced task deadline; failures/cancellation terminate outstanding processes and phase files are removed in finally. The existing systemd control group handles service-stop cleanup, while existing recovery removes abandoned flat job files after an interruption. cpu_processing records capacity and actual dispatch concurrency. Terrain mutation, deterministic scenery and ZIP packaging remain serial.


Side-road shoulder consistency: blendTerrain delegates to blendTerrainSet, which shares the untouched terrain baseline and nearest-distance field across all provided surfaces. The primary single-road call retains the same math. Secondary roads, cubic connector strips and turnarounds are grouped into stable ownership corridors and blended together; this prevents order-dependent overwriting of an earlier road edge by another road's outer fade. Each clearance pass additionally masks nearby other-owner support cells, using expanded bounding-box rejection before constructing a mask. Main-road/bridge masks and bounded clearance remain authoritative. This avoids a full N-by-grid ownership allocation while preserving native terrain contact around neighboring side roads.

Tunnel exports: BeamTunnels detects selected collinear tunnel=yes spans independently of bridges. Approach samples replace underground DEM heights before ordinary road smoothing. Tunnel spans protect native terrain from ordinary corridor flattening and suppress side-road junction preparation inside the bore. BeamTunnels.build emits a U-section concrete collision shell with open portal caps, estimated lights, and portal exclusions. LayerMap byte 255 marks native terrain holes (BeamNG terrain format: https://documentation.beamng.com/modding/levels/level_formats/terrain/). Original terrain triangles in affected cells are clipped against bounded sloped excavation prisms below the ceiling; retained triangles preserve overburden and use the aerial fallback texture. This avoids both an open trench and invisible native collision inside the tunnel. Cell budgets, supported span types, approach distances, pavement width and grade checks bound work. Reports and job warnings explicitly distinguish estimates from surveyed engineering. No new elevation source is claimed.

Divided-road connectivity: RoadGraph version 2 seeds one-way edges before remaining two-way edges. Per-candidate visitation prevents edge reuse inside one track, while global visitation suppresses redundant seeds without preventing opposite carriageways from sharing two-way approaches. The accumulated whole-chain direction constrains every continuation, including after a two-way segment; pairwise compatibility alone would allow incompatible one-way ends. Direction flips with the chain during backward extension. Existing reference/name, highway and heading checks remain. This constructs bounded continuous candidates rather than general destination routing. API travel_direction selects the first nonzero oriented member rather than assuming the first member represents the whole candidate. Custom snapping retains nearest-road guards and prefers a candidate matching click order on shared approaches.

Migration 017 adds import_jobs.analysis_version. New analyses record RoadGraph::VERSION; bin/rescore.php invokes RoadGraphRefresh for outdated active imports before geometry/scoring refresh. Importer::rebuild locks the region/import, replaces only derived candidates/scores/members in one transaction, validates nonempty replacement when prior roads existed, refreshes geometry keys, clears the derived combination cache and advances the version. Failure rolls back all changes. Raw OSM, coverage, imported_at and user snapshots remain. No source-file access, provider request or web-request preprocessing is introduced.

Large fixed bridges: BeamStructures accepts bridge=yes/viaduct with beam/slab or unspecified structure, up to 2,000 m per merged span and 16 spans per export. Spans over 200 m use 50 m approach anchors and require chord/length >=0.85; short spans retain their original 20 m sampling anchors, 25 m selection approaches and 0.95 chord threshold. Grade remains bounded to 12%; clearance over terrain is limited to 150 m. Terrain above the inferred deck is refused rather than excavated. Existing structure masks, bridge approach correction, generic barriers and 25 m support sampling remain; material ground type is explicitly concrete. This is a generic fixed-deck estimate, not inferred suspension/arch engineering. Ordinary-road and short-bridge elevation methods are unchanged.

Tunnel terrain repair: excavation now retains original ground already below the road. When terrain inside the open bore/approaches must be cut, its clipped surface is lowered to 5 cm below pavement instead of being deleted. UVs and collision remain on the replacement terrain patch; the hillside above the ceiling stays intact. This closes visible and physical holes alongside the road and portal tapers. It does not add separate collision shoulder objects or change ordinary-road shoulders. Regenerate exports to apply the repair; existing ZIPs are untouched.

Bridge undersides: bridges on explicit pavement now include a closed, outward-facing concrete shell beneath the road, with bottom, side and end faces. It follows the exact pavement cross-sections and mapped span endpoints, adds 0.5 m (about 1.64 ft) of generic visible deck depth, and casts shadows. This is visual geometry only: pavement collision, supports, barriers, road elevations and native terrain remain unchanged. Native MeshRoad decks already have underside geometry and do not receive a duplicate shell. Regenerate exports to apply the fix.

Tunnel vertical seam repair: retaining excavation floors alone did not join their raised boundary to the original hillside. The replacement terrain patch now includes inward-facing side/end faces along excavation boundaries and narrow portal rims. Faces hidden inside adjoining excavation volumes are removed; the usable bore is subtracted from portal rims so they cannot close the driving entrance. The ceiling above the tunnel and lower original ground are retained. Ray-based tests inspect vertical joins and open passages in addition to projected surface-area tests. This adds faces to the existing tunnel terrain patch, not standalone roadside collision shoulder objects. Fresh generation and in-game validation remain required.
